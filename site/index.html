The U30 Pro, as a Linux router with its own screen

OpenWrt next to Android on the ZTE U30 Pro (MU5358, Unisoc UMS9632). Mobile data, Wi-Fi 6 hotspot, SSH over USB, and the hotspot's round screen as a router's dashboard, in English, Turkish and Chinese. Android stays, and every reboot goes back to it by itself.

Read the status first Source on GitHub Sponsor

The sibling of MU300 Linux (ZTE F50 and U30 Air), by the same one person in Turkey.

Status: a working research port

No installer, no release yet. Everything here was brought up and tested on one rooted unit, by hand, with the scripts in the repository. It is published so that the work is visible and others can follow it. If you are not comfortable with adb, Magisk root, partitions and a serial console, wait for an installer. There is a web installer page (Chrome or Edge, over USB); it is new, and its browser side has so far only been run against its own demo, not a real device.

What it already does well: a 3-hour soak with every check green (USB, network registration, mobile data, ping, Wi-Fi), no kernel oops, the NV partitions byte-for-byte unchanged and memory flat; six reboot cycles in a row with everything coming up by itself.

What works

  • Mobile data (LTE)Android's own modem daemons in a chroot, as on MU300 Linux. 14-19 Mbit/s where Android did 11-12 on the same spot.
  • Wi-Fi 6 hotspotAIC8800D80X2, 5 GHz, HE80, WPA2, with the board's own MAC and calibration.
  • The screenA dashboard on the round screen, in English, Turkish and Chinese: home with a live throughput graph, network, Wi-Fi with a QR code to join, clients, traffic, SMS, battery, system, settings, power and log. One 1.6 MB binary, about 6 MB of RAM, 0.5 % of the CPU with the screen on. The launcher-look "classic" interface stays as an option.
  • ButtonsPower: screen on/off, held: power off. Wi-Fi key held: hotspot off/on.
  • USB network and SSHPlug it into a computer: ssh root@192.168.58.1, plus a serial console.
  • GPUMali-G57 with OpenGL ES 3.2, EGL 1.5 and Vulkan through Android's driver, loaded on demand.
  • Android staysLinux only ever starts as a one-shot trial; reboot, power-off, a kernel oops or a failed boot all land in Android.
  • Not yetSuspend and power saving, charging verified below 100 %, long battery-only runs, Bluetooth, NFC, SIM tray detection, USB OTG, calls and audio, sending SMS, OpenCL.

The screen

The U30 Pro has a round 240×240 screen and a touch panel. Under Linux it is a router's dashboard: u30ui2, written in C straight onto the kernel's DRM, in English, Turkish and Simplified Chinese (the language is a setting on the screen). Swipe sideways for the pages, down to go home or to close what is open. Locked at start (hold to unlock), it locks again after two minutes without a touch; the power key switches the screen, and the timeout switches it off.

It is new: the dashboard replaced the launcher-look interface as the default on 2026-10-30, and so far it has run on one unit. The whole thing is one static 1.6 MB binary with the fonts inside, about 6 MB of RAM and 0.5 % of the CPU with the screen on and the home page's live graph; while the screen is off nothing is drawn and the readings slow to one pass in 30 seconds. The classic interface

The first interface, u30ui, in the look of the U30's Android launcher (the same petals, colours and pages, without Android), stays in the system as the "classic" interface. Either one's settings page switches to the other.

One detail worth telling: the panel is mounted upside down, and turning the picture on the CPU made every moving frame tear, because the rows then reached the panel against its own scan direction. Now the panel turns the picture itself (its MADCTL register, set by a tiny kernel module) and the tearing is gone.

How it boots

  1. Android asks for slot b, once

    From rooted Android, a one-shot "try slot b" request goes into the misc partition.

  2. LK starts slot b

    The board's own GKI 6.6 kernel, rebuilt with a small fragment, with our init_boot_b ramdisk.

  3. The ramdisk takes it back at once

    It loads the vendor modules, brings up USB and puts misc back to Android 1.6 seconds in, before anything can go wrong.

  4. OpenWrt starts

    From its own region of the eMMC behind userdata. The modem gets the NV partitions only as copies in RAM; the real NV is never written.

Slot a and the NV partitions are never written. Any reboot, power-off, kernel oops (the kernel restarts on one) or failed boot ends in Android.

Build it

For people who want to follow the work. Every step runs from a computer with Docker and adb, against a rooted U30 Pro, after a full backup.

  1. Back up everything: tools/backup-full.sh OUTDIR (every partition, checked against hashes taken on the device).
  2. Kernel: kernel/build.sh in kernel/Dockerfile's container (GKI android15-6.6 at the device's own commit, plus kernel/mu5358-linux.fragment).
  3. Boot images: boot/build-initboot.py makes init_boot_b (and boot_b) from the stock images and boot/init.
  4. Root file system: openwrt/build-rootfs.sh from MU300 Linux's OpenWrt release; openwrt/customize.sh makes it this board's.
  5. Android's files (modem daemons, firmware, GPU driver): pulled from your own device by the scripts in modem/ and gpu/. They are not in the repository.

The system as it runs (services, hardware status, known behaviour, where the logs are) is in docs/GKI-SYSTEM.md.

Questions people ask

Is it the same as MU300 Linux?

It is built on MU300 Linux's OpenWrt and its modem tools, but the U30 Pro is a different chip (UMS9632), a different Wi-Fi chip, a screen and a touch panel, and a newer Android (15) with a GKI kernel. So the kernel side, the boot path, the modem's NV handling, Wi-Fi and everything on the screen are new. MU300 Linux does not support the U30 Pro.

Can it brick my device?

The project never writes slot a or the NV partitions, and Linux is never made the default boot. Still, writing partitions on a rooted device is never without risk; that is why the first step is a full backup.

Why OpenWrt and not Ubuntu?

It is light (the whole system idles in a few dozen MB), it is a router first, and MU300 Linux's OpenWrt already brings the modem tools. Ubuntu may come later.

When will there be an installer?

After battery-only operation and charging are verified and a 24-hour soak passes. Follow the repository for news.
