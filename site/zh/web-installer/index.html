网页安装器

开始之前

  • 一台已用 Magisk root 的中兴 U30 Pro（MU5358，紫光展锐 UMS9632），且 Android 从槽位 a 运行。页面不给设备 root，也不解锁 bootloader；它拒绝任何其他设备。
  • Windows、macOS 或 Linux 上的 Chrome、Edge 或其他 Chromium 浏览器。Firefox 和 Safari 没有 WebUSB。
  • Android 中已打开 USB 调试，设备已接好，且没有其他程序占用它。正在运行的 adb 服务会占用它（用 adb kill-server 停止），另一个打开了本页面的标签页也会。
  • 给 shell 的 root 权限：第一次时 Magisk 会在设备上询问（“Shell”请求 root）。请允许。
  • 发布版本的文件，从项目的发布页下载：SHA256SUMS、SHA256SUMS.sig、mu5358-openwrt.img.gz（约 53 MB）、mu5358-kernel.Image.gz、mu5358-ramdisk.tar.gz、mu5358-tools.tar.gz、mu5358-install.sh 和 android-files.txt。页面会自行下载它们：来自项目的发布版本镜像（仓库的一个分支，GitHub 允许网页读取它；GitHub 自己的发布下载则不回应网页）。镜像没有某个版本的副本时，由您下载文件并在页面上选择。
  • 如果要用 userdata 之后的空间：从 Android 的 /data 划出 Linux 的那份之后，/data 还得至少剩 4 GiB 空闲。
  • 所安装系统中 root 的密码（至少 6 个字符），在页面上输入：它成为 SSH 和网页面板的 root 密码，否则 OpenWrt 会让它们没有密码。设备只收到它的哈希。

页面做什么，设备上运行什么

页面是一个小型 adb 客户端。它通过 GitHub 的 API 读取发布版本列表，连同 GitHub 为每个文件计算的 SHA-256。无论文件是页面下载的还是您选择的，它都在浏览器中检查它们：SHA256SUMS 必须与 GitHub 的校验和一致，并且必须带有项目发布密钥的签名（SHA256SUMS.sig，usign 格式的 Ed25519 签名，用内置在页面里的密钥校验：源码中的 installer/release.pub，编号 15fd2f702186c19e）；其他每个文件必须与 SHA256SUMS 中写的校验和一致。没有项目签名的 SHA256SUMS 一律拒绝，无论 GitHub 怎么说。只有这之后才会有东西发往设备。

在设备上，一切都由发布版本自己的脚本 mu5358-install.sh 完成，通过 Magisk 的 su 以 root 运行。页面把它和发布版本的文件放到 /data/local/tmp/mu5358-web；脚本把它们移进 root 自己的目录（/data/adb/mu5358），使用之前再全部检查一遍。然后它把安装作为一项独立的任务运行，页面则跟踪这项任务：各个步骤、日志和结果。

  • 安装（或更新）：系统 OpenWrt，连同这台设备自己的厂商文件（模块、固件、Wi-Fi 校准、基带和 GPU 的用户空间，从它的 Android 中复制），以及槽位 b 的启动镜像。您在页面上输入的 root 密码会设置到系统中（以其哈希的形式；设备从不会看到密码本身）。
  • 启动一次 Linux：Linux 启动一次；下一次重启又是 Android。
  • 卸载：槽位 b 放回 Android 的启动镜像，系统被擦除，空间还给 Android，除非您选择保留。
  • 备份：下载第一次安装所覆盖的内容（槽位 b 的 boot 和 init_boot，以及 misc）。

它从不写入的东西：槽位 a、NV 分区（射频校准、IMEI：nr_*nv*、prodnv、calinv、miscdata、persist、ztepersist）、Android 的任何数据，以及除 userdata 末端之外分区表的任何条目。

Linux 装在哪里：userdata 之后，还是 fulldumpdb

userdata 之后（推荐）fulldumpdb
Linux 的空间4、8 或 16 GiB，由您选择（默认 4 GiB）2 GiB
会改变什么Android 的 userdata 分区提前结束。它的文件系统在运行中被缩小；Android 的东西一样都不会被擦除。中途 Android 必须重启一次：页面会做这件事，重新连接后继续。不重新分区。厂商的崩溃转储分区在正常设备上是空的，系统就装在那里。
移除它把空间还给 userdata（Android 下次启动时自动扩展进去），或者留着这块空区域给以后的安装。fulldumpdb 恢复为全零，和出厂时一样。

Linux 只启动一次，从不默认启动

安装不会改变启动哪个系统：每次重启启动的仍然是 Android。只有当您按下“重启进入 Linux 一次”时，Linux 才会启动。设备随后写入它启动控制块（misc）的 32 个字节，读回核对，然后重启；槽位 b 就被尝试这一次。无论 Linux 里发生什么，下一次重启又是 Android：要离开一个起不来的 Linux，断开电源或长按电源键即可。页面本身无法管理 Linux；请通过 USB 上的 SSH 访问它。

如果标签页被关闭或数据线脱落

安装是设备上的一项任务。它不需要本页面：关闭标签页、浏览器崩溃或电脑休眠，结束的只是页面对它的观察，而不是任务本身。重新连接后，页面会显示进行到哪一步，并跟踪到结束。

在这一步中断设备的状态
发送和检查文件分区中没有写入任何内容。它启动 Android。
在 userdata 之后腾出空间缩小由内核自己的 f2fs 代码完成，它会先检查空闲空间并做一次试运行；分区表在那之后才修改。如果断电发生在两者之间，Android 下次启动时会把文件系统扩回去。它启动 Android。
复制启动链、写入系统或槽位 b 的 boot只写入槽位 b 和 Linux 的空间，从不写槽位 a。启动控制块仍然指向 Android：它启动 Android。请再次运行安装。
安装完成之后Android，直到您请求启动一次 Linux。

卸载的顺序正好相反：先是 Android 的启动控制块，再从槽位 a 把启动镜像放回槽位 b，最后擦除系统。无论在哪一步中断，设备启动的都是 Android。

如果浏览器无法打开设备

所有系统

正在运行的 adb 服务（Android Studio、终端里的 adb、scrcpy）占用了设备，或者另一个标签页打开了本页面并连接着设备。同一时间只能有一个程序与设备通信。

adb kill-server，关闭这些程序以及那个标签页，然后重新连接。如果原因在此，页面会提示“有别的程序正在使用设备”。

Windows

浏览器只能使用装有 WinUSB 驱动的接口。U30 Pro 的 adb 接口是否会自行从 Windows 得到这个驱动尚未实测；如果那里装的是厂商自己的 adb 驱动，浏览器就会被挡住。

在设备管理器中查看设备的“ADB Interface”。如果它用的是其他驱动或没有驱动，请安装 Google 的 USB 驱动（它就是 WinUSB），或用 Zadig 给该接口绑定 WinUSB。只改 adb 接口，不要改网络或调制解调器接口。

Linux

设备节点属于 root，浏览器无权写入。

为 adb 接口添加一条 udev 规则，然后重新插入设备： 
echo 'SUBSYSTEM=="usb", ATTR{bInterfaceClass}=="ff", ATTR{bInterfaceSubClass}=="42", MODE="0660", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/51-adb-webusb.rules
sudo udevadm control --reload && sudo udevadm trigger
以 snap 或 flatpak 方式安装的浏览器可能还需要单独的 USB 权限。

macOS

无需安装任何东西。只有其他程序占用设备时浏览器才会受阻。

退出该程序。

页面能看到和保存什么

  • 它访问 GitHub 的 API 获取发布版本列表，访问本站获取自己的文件。除此之外没有别的：没有统计分析，没有来自其他网站的字体或脚本。页面的策略（它的 CSP）不允许它连接任何其他地方。
  • 它从不向设备索取 IMEI、IMSI、ICCID 或电话号码，也从不读取 NV 分区。
  • 序列号以遮盖形式显示。日志中，无论在屏幕上还是在可保存的文件里，序列号、身份号码、电话号码、MAC 地址和密钥都会被遮盖。
  • 它在浏览器为本站提供的存储中只保存一样东西：此浏览器的 adb 密钥；您允许一次之后，设备就会记住它。
